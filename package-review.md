- **The package addresses the delivery failure.** Users can select/copy one of four portable folders through the README. Relative `.agents/skills` links target the canonical folders. Evaluation tooling, case definitions and historical research are separate from installed skill resources. Raw execution trees, accumulated review rounds and experiment drivers are absent from the maintained source package.
- **Retained evaluation scope has concrete consumers.** The 36 cases comprise 17 focused operations and 19 complete scenarios. The evaluation files include 287 fixture files, 53 phase requests, 11 overlays, 9 retained source/provenance inputs and 97 definitions/checkers/guides. They exercise distinct decisions, review/resumption behavior, compatibility, setup and delivery boundaries through the existing runner. The added PR-scope case distinguishes a required generated CSV from unrelated preview output; the two transfer cases cover an understood local feature and consequential filesystem handling. I found no new framework, service or redundant execution archive that warrants rejection. Detailed semantic validation of every legacy case was outside this bounded review.
- **Original and adapted inputs are distinguishable.** Both transfer cases' staged copied-file hashes match their provenance. Their active checkers equal exactly the declared adaptations of archived originals, and phase requests equal the original requests plus the declared invocation. The preserved checker versions and freeze records establish provenance, rather than acting as additional maintained implementations. The nested-output fixture's original-byte verification remains recorded in [storage review](storage-review.md); offline tests use that maintained fixture rather than a removed run directory.
- **Historical retrieval works.** A fresh read-only remote query returned `a24b140ddda594bec61ae42ac272d3225892cfb5` for `refs/heads/codex/evidence-before-repair`. All 17 targets in [historical-links.json](historical-links.json) resolve to Git blobs/trees at that commit. The documented fetch/show procedure can retrieve originals without restoring them into the working source tree. No claim is made that removing current paths shrinks retained Git history.
- **Documented setup has actual fresh-export evidence.** Inspected [clean-check.json](clean-check.json) and its producer: the staged tree was exported with `git archive`, initialized as a new repository, given a new Python 3.12 environment, installed from `requirements-dev.txt`, and had its hooks installed. The complete hook gate exited zero in 77.828 seconds, with 250 tests passing plus lint/format, bundle/link and canary-input checks. No historical archive was restored. This establishes local source-checkout operation on the recorded macOS/Python environment; it is not a fresh Linux CI or Codex UI-installation result.
- **Prior storage correction is present.** Staged `tools/canary.py` and `tools/check.py` match the independently rechecked hashes in [storage review](storage-review.md). Alias rejection remains blocking, and collection discovery remains bounded. No further storage issue emerged from this package inspection.

The ordinary full gate has a measured maintenance cost of about 78 seconds on this machine, but invokes no models; expensive evaluation stays separately selected under the documented policy. Removing the retained verification system merely because it has more files than the four skills would discard requested regression coverage without evidence of a better outcome. Conversely, the passing gate alone does not establish skill usefulness; the separate behavior reviews and human assessment retain that responsibility.
