# Review the implementation plan

Read the source requirements, confirmed design, exact plan version, relevant code and actual check configuration. Assess the shared [plan contract](../assets/implementation-plan.template.md), then use the [review feedback contract and example](../assets/review.template.md). Do not edit the plan or implementation during review. Disclose whether the review is independent or self-review.

Check delivery order, dependency/boundary reasons, acceptance and feasibility against the current repository. Planned commands must be distinguished from available ones; zero collected tests cannot establish success. A short combined note or single increment can be sufficient. Block for a concrete contract, dependency, risk or usability consequence, not preferred headings, test counts or separate documents.

On recheck, compare the relevant revision and evidence. Cite an unchanged verified resolution while it remains applicable; changed assumptions/content or missing verification require checking the full affected contract. Honor required rechecks and preserve original findings. Do not reopen unrelated completed decisions or continue cosmetic cycles.

After writing feedback, load the Review section of [artifact checks](../references/artifact-checks.md). Correct supported reporting defects; disclose unresolved issues without a new self-review report or round.
