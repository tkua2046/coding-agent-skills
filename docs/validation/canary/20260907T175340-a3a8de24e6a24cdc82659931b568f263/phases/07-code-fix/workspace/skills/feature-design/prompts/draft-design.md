# Draft or revise the design

Read the original requirements, confirmed clarifications, relevant code and current design. Use the shared [design contract and adaptable example](../assets/design.template.md); the reviewer assesses the same responsibilities. Distinguish verified facts, proposed choices and unresolved decisions. Research an uncertain external guarantee when it can change the choice, retaining the source and separating inference from its guarantee.

Amend the existing design for a local extension. Refresh the current decision, consequence and example when scope changes; preserve unrelated accepted decisions and original sources. Link an immutable reviewed version, or capture it once when otherwise unavailable. A new feature request alone is not a reason for a separate design or another full review. Private helper/test changes ordinarily leave the design alone.

Use the repository's conventions and expand only material uncertainty or risk. A local design and next implementation outcome may share one note. Keep execution status in the existing plan/handoff; the design owns decision status and links to delivery status. A design-only request stops before implementation.

After drafting or amending, load the Design section of [artifact checks](../references/artifact-checks.md). Correct supported problems; report unresolved material decisions. The check is silent otherwise and creates neither a report nor another review round.
