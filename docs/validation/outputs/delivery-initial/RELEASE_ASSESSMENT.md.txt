## Actual change and compatibility assessment

The complete diff from the approved/tested commit to HEAD changes only `app.py`:

```diff
-def label(value):
-    return value.strip().upper()
+def label(value, transform=None):
+    return transform(value) if transform else value.strip().upper()
```

The candidate adds an optional transform. For an ordinary supplied callable, it passes the original input directly to that callable and returns its result. For example, `label(" AbC ", str.lower)` returns `" abc "`. Existing `label(" AbC ")` still returns `"ABC"`; explicit `None` selects the same default. Selection is truthiness-based, so a falsey transform also selects the default. There is no supplied requirement establishing a broader callback contract.

The observed existing one-argument behavior is preserved. Proposed 0.2.0 is reasonable for this additive capability under the user's requested pre-1.0 release, but a minor bump is not established as mandatory by a repository 0.x policy. No breaking change to the demonstrated existing behavior was found. This is not a claim of exhaustive compatibility.

The existing changelog says “Configurable labels preserve existing defaults.” It remains under Unreleased and does not yet identify the callable API. Both VERSION and CHANGELOG are unchanged between the comparison commit and HEAD.
