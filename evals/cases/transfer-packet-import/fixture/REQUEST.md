We receive small ZIP packets of workshop handouts from partner organizations. Our local helper lists the packet and imports it into a new folder; the current direct extraction can leave confusing partial folders, and a partner's archive must not choose where files go on our machine. Please make preview and import safe, add meaningful regression tests, and document the operating boundary and failure/retry behavior.

Keep `preview(archive)` and `import_packet(archive, destination)` and both CLI commands compatible for ordinary valid packets. They return/print sorted relative file names, omitting explicit directory entries. Preserve file bytes and support spaces and Unicode in names.

Both preview and import must reject invalid member metadata with `ValueError`: absolute paths, backslashes, colons, empty or dot/dot-dot path components (a single trailing slash on a directory is allowed), duplicate paths, and a file used as a parent directory. A file and directory with the same path conflict. Reject Unix symlinks and other special file types; ordinary ZIP entries without Unix file-type metadata are valid. Preview must not extract or create files.

Import is allowed only to a previously absent destination, including rejecting a dangling symlink. On success the complete folder should become visible together. On any validation, archive-read, filesystem-write, or final-placement failure, leave the destination absent and remove your temporary work. Existing destinations and other files in the parent must remain unchanged. After correcting a bad packet, the same destination can be retried normally. Existing destinations raise `FileExistsError`; corrupted ZIP data can raise `BadZipFile`, `ValueError`, or an appropriate I/O error. The CLI must report failure without a traceback or a misleading success listing.

The destination's parent already exists and is trusted. No other process changes the archive or destination during import. This is a small offline helper: concurrent-writer protection, archive resource quotas, encrypted archives, preserving permissions/mtime, and crash/power-loss durability are outside this task. Do not broaden it into a service.

Local implementation and checks are authorized; choose the amount of design and verification needed for this filesystem boundary. Use standard-library Python and the existing test command. Work only in this supplied project; no packages, network, commits, or publishing. Finish with a usable account of the safety choice, checks actually run, and any unresolved issue so a colleague can maintain and retry the helper.
