# Clarify the feature

1. **Establish the contract.** Read the request, confirmed decisions and the relevant repository instructions/code. Identify the intended behavior and compatibility obligations. Use routine reversible defaults where supported; do not ask the owner to reconfirm settled facts.
2. **Resolve consequential unknowns.** Inspect a caller, reproduce behavior or run a bounded authorized experiment only when its result can change the decision. Reuse applicable baseline evidence. If promises conflict, explain the concrete consequence and ask for the unresolved precedence; an inferred exception remains a proposal. Separate observed results, pre-existing failures and missing evidence.
3. **State what is settled and what remains.** Preserve the original request and confirmed answers at their existing source. A response can suffice; update an existing note when durable clarification is useful or requested. If a material answer is pending, continue independent work while leaving the dependent decision open. An intake-only request ends here; an authorized implementation task may continue once its facts are sufficient.
4. **Finish for the reader.** Use the Intake section of [final checks](../references/artifact-checks.md). Put the conclusion and any consequential unanswered question where they are easy to find; retain useful support without copying logs. The [clarification example](../assets/spec-addendum.template.md) is optional when a note helps. Deliver without adding a self-review report or an invented next step.
