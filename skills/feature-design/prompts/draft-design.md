# Draft or amend a design

1. **Ground the decision.** Read original requirements, confirmed clarifications, relevant code and the existing design. Resolve a factual unknown only if it could change the approach. Attribute consequential external guarantees and distinguish inference or uncertainty from verified facts.
2. **Choose the smallest sufficient approach.** Explain the behavior, choice, reason and important consequence. Include an example that distinguishes the consequential success/failure behavior. Cover compatibility and state ownership where affected. When failure can leave persistent/external effects, explain the usable state after interruption and conditions for retry. Discuss a credible alternative only when its tradeoff helps decide; do not inventory speculative architectures or private code/tests.
3. **Update the right scope.** For a local extension, amend affected decisions and examples while preserving unrelated accepted work and original sources. Reuse existing history; capture an otherwise unavailable reviewed original once. Private helper/test changes normally leave the design alone. New real scope must remain represented even when it needs more detail. Honor requested review; a design-only task stops before implementation.
4. **Check substance, then finish for the reader.** Use the Design section of [final checks](../references/artifact-checks.md); correct material gaps, then organize the current choice and consequences for a quick read. Use the [design example](../assets/design.template.md) only if it helps. A short local note can be complete. Deliver the decision and any material remaining question; no extra document or polishing round is needed.
