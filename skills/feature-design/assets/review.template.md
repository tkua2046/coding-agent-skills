# Optional review feedback shape

Use this when organizing the final feedback; alternate clear formats are equally valid.

**Verdict:** [ready / material changes needed / consequential decision pending].
**Scope and evidence:** [reviewed revision, actual review mode and meaningful evidence limits].

For an actionable concern: [location] → [trigger and consequence] → [sufficient correction and how to verify it]. Use a stable ID when tracking the finding through revisions. Separate material issues from optional presentation suggestions.

On recheck, link the original concern and state its disposition on the current revision. Preserve the original finding; distinguish author-reported repair, reviewer-verified resolution, evidence-backed rebuttal and accepted limitation. A partial fix remains open. Do not fabricate human acceptance or runtime verification.

## Example

Needs changes on D2. R1 remains open: an invalid refresh still replaces usable cached data. Preserve the previous value when validation fails; verify that preservation and a later valid refresh. This is a design review, not an executed runtime check.

When no material issue remains, a supported ready verdict suffices. Do not invent a next task or another polishing round.
