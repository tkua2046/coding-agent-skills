# Review the implementation plan

Read the source requirements, existing decisions, exact plan version, relevant code and actual check configuration. Assess the shared [plan contract](../assets/implementation-plan.template.md), then use the [review feedback contract and example](../assets/review.template.md). Do not edit the plan or implementation during review. Disclose whether the review is independent or self-review.

Check delivery order, dependency/boundary reasons, acceptance and feasibility against the original goal and current repository. Assess the overall implementation and coordination burden, even when each stage appears feasible. Planned commands remain distinct from available ones; zero collected tests cannot establish success. A short combined note or single increment can suffice. Block for concrete contract, dependency, risk, maintenance or usability consequences; preferences do not require more process.

On recheck, compare the relevant revision and evidence. Cite an unchanged verified resolution while it remains applicable; changed assumptions/content or missing verification require checking the full affected contract. Honor required rechecks and preserve original findings. Do not reopen unrelated completed decisions or continue cosmetic cycles.

After writing feedback, load the Review section of [artifact checks](../references/artifact-checks.md). Correct supported reporting defects; disclose unresolved issues without a new self-review report or round.
